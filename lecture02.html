Overview 1: What Is Voice AI?

What Is Transcription (STT/ASR)?

Voice AI transcribes spoken audio into text. This is also called STT (Speech to Text) or ASR (Automatic Speech Recognition). Once audio becomes text, it can be searched, analyzed, and summarized.

  • Audio alone cannot be searched or analyzed
  • Transcription is a preprocessing step for generative AI
  • This class uses the Whisper speech recognition model

Whisper Model

SAKURA AI Engine provides the Whisper speech recognition model. We will use whisper-large-v3-turbo, a faster derivative of the large-v3 model.

  • Open-source model released by OpenAI
  • Internally processes audio in about 30-second units
  • API limit: 30 minutes or 30 MB per request

30 seconds vs 30 minutes

30 seconds is Whisper's internal processing unit, not the upload limit. You can send up to 30 minutes (30 MB) in one API request.

Real-Time vs Batch Processing

Type Note
Real-time Transcribes while speaking; used for subtitles and interpretation
Batch Records first, then transcribes later; simpler and suited for meeting minutes

This class uses synchronous batch processing: send a file and wait for the result.

Factors Affecting Accuracy

Even the same AI can produce very different results depending on conditions.

  • Sound quality: background noise and distance from the microphone
  • Speaking style: speed, volume, and overlapping voices
  • Words: technical terms, proper nouns, abbreviations, hesitations
  • Language: differences between English and Thai, mixed languages

Business Use Cases

Transcription solves the problem of not being able to search or analyze audio directly.

  • Preparing meeting minutes
  • Call center call records
  • Video subtitle creation

Hands-On 1: Transcribe Sample Audio

Transcribe prepared English audio files with curl and compare short and long samples.

Required

  • Create the work folder 02_AI_ASR
  • Download a short sample audio file
  • Run the Transcription API with curl
  • Run the same command on long sample audio and compare

Prerequisites

We use the environment created in Lecture 1. Make sure your Account Token environment variable is set.

echo $AI_ENGINE_TOKEN
# If nothing appears, set it again
export AI_ENGINE_TOKEN="<issued account token>"

Steps

  1. STEP 1: Create the work folder and download sample audio

    Create 02_AI_ASR in your WSL home directory and download sample_short_en.wav.

    Download sample_short_en.wav

    mkdir -p ~/02_AI_ASR
cd ~/02_AI_ASR
curl -O https://vtmacs.github.io/ameicc2026/assets/downloads/sample_short_en.wav
ls -l

    Use -O (uppercase) when the URL contains the file name. Use -o (lowercase) when you want to choose your own file name.

  2. STEP 2: Run the Transcription API

    Send the audio file to the API with model=whisper-large-v3-turbo and language=en.

    curl --request POST \
  --url https://api.ai.sakura.ad.jp/v1/audio/transcriptions \
  --header 'Accept: application/json' \
  --header "Authorization: Bearer ${AI_ENGINE_TOKEN}" \
  --header 'Content-Type: multipart/form-data' \
  --form 'file=@sample_short_en.wav' \
  --form 'model=whisper-large-v3-turbo' \
  --form 'language=en'

    Always specify language=en for English. Without it, transcription quality may drop.

  3. STEP 3: Check the short audio result

    The response is JSON with a text field. Compare the output with the original script below.

    Original text of sample_short_en.wav

    Japan holds nearly 7,000 islands (the biggest being Honshu), making Japan the 7th largest island in the world!

    Check whether numbers and proper nouns (7,000 / Honshu) are correct.

  4. STEP 4: Transcribe the long sample audio

    Run the same API command on sample_long_en.wav and compare with the script.

    Download sample_long_en.wav

    curl -O https://vtmacs.github.io/ameicc2026/assets/downloads/sample_long_en.wav

    curl --request POST \
  --url https://api.ai.sakura.ad.jp/v1/audio/transcriptions \
  --header "Authorization: Bearer ${AI_ENGINE_TOKEN}" \
  --header 'Content-Type: multipart/form-data' \
  --form 'file=@sample_long_en.wav' \
  --form 'model=whisper-large-v3-turbo' \
  --form 'language=en'

    Original text of sample_long_en.wav

    Safaris are perhaps the greatest tourism draw in Africa and the highlight for many visitors. The Kruger National Park (KNP) lies in the north-east of South Africa and runs along the border of Mozambique in the east, Zimbabwe in the north, and the southern border is the Crocodile River. The park covers 19,500 km² and is divided in 14 different ecozones, each supporting different wildlife. Examples of on-site activities include hunting, fishing, photography, bird watching, and visiting parks and studying information about the ecosystem. Some animals, such as elephants and giraffes, tend to approach closely to cars and standard equipment will allow good viewing.

    Look for missing words and whether the number of transcription errors increased compared with the short sample.

Overview 2: Passing Audio to the API

How Audio Reaches the API

The Transcription API cannot receive a URL; it receives the audio file itself. You must first download the audio from the cloud to your own computer, then upload it to the API.

  • Download: bring audio from the cloud to your PC with curl -o
  • Upload: send the local file with --form file=@filename

Synchronous vs Asynchronous Processing

When asking AI to process data, there are two ways to wait.

Type Note
Synchronous Send, wait until processing finishes, receive the result directly. Simple, but not suitable for very long processing.
Asynchronous Send once, then come back later to fetch the result. Suitable for long or large-scale processing.

This class uses the synchronous Transcription API.

API Limits

Because the API is synchronous, there is a limit to how much audio you can send at once.

  • Maximum per request: 30 minutes or 30 MB
  • Internally, Whisper splits audio into about 30-second segments for processing
  • Long meetings must be split before sending, or handled with a separate asynchronous system

30 seconds is not the upload limit

30 seconds is Whisper's internal processing unit. The API upload limit is 30 minutes or 30 MB. Do not confuse the two.

Overview 3: Transcription Accuracy and Beyond

Transcription Is Not Always Accurate

Even the best models make mistakes. The most important first step is to check the output.

  • Proper nouns: person names, university names, product names may turn into similar-sounding words
  • Numbers and dates: 15 vs 50, Wednesday vs Thursday, etc.
  • Homophones: English two / to / too may be misjudged from context
  • Hesitations: "um" and "uh" are transcribed as-is

The most reliable check is to compare the transcript with the script sentence by sentence.

Transcription Errors Carry Over to Later Steps

If the transcription is wrong, the summary is built on that error. Because the summary looks natural, the mistake becomes hard to notice. Always check the transcript before summarizing.

What Happens When Speaker Information Is Missing?

Transcription produces a single block of text. It does not label who spoke each part.

  • Decisions and deadlines can still be extracted
  • The person responsible cannot be reliably extracted without speaker labels
  • Diarization is the technique that identifies speakers, but Whisper does not support it

Hands-On 3: Check Transcription and Summarize

Compare the long English transcription with the script, correct errors, summarize with Python, and compare before and after correction.

Required

  • Compare the English transcription results with the script sentence by sentence
  • Correct errors by hand and save the text
  • Summarize the corrected text using Python
  • Compare summaries before and after correction

Steps

  1. STEP 1: Compare the transcript with the script

    Copy the transcription result from WSL and compare it with the original script line by line. Check proper nouns first, then numbers and dates, and finally the meaning of each sentence.

  2. STEP 2: Write misrecognitions on the worksheet

    Record any differences you find. You do not need to write everything; focus on clear mistakes.

  3. STEP 3: Correct errors and save

    Create sample_long_en.txt with nano, paste the transcription, and correct each error.

    cd ~/02_AI_ASR
nano sample_long_en.txt
# Right-click to paste, then fix errors
# Save: Ctrl+O, then Enter  Exit: Ctrl+X
cat sample_long_en.txt
  4. STEP 4: Summarize the corrected text

    Use Python and urllib.request to call chat/completions and summarize the file.

    python3 -c "
import os, json, urllib.request
token = os.environ.get('AI_ENGINE_TOKEN')
text = open('sample_long_en.txt', encoding='utf-8').read()
payload = {'model': 'gpt-oss-120b',
           'messages': [{'role': 'user',
                         'content': f'Summarize this in English:\n\n{text}'}]}
req = urllib.request.Request(
    'https://api.ai.sakura.ad.jp/v1/chat/completions',
    data=json.dumps(payload).encode('utf-8'),
    headers={'Authorization': f'Bearer {token}',
             'Content-Type': 'application/json'})
with urllib.request.urlopen(req) as res:
    print(res.read().decode('utf-8'))
"
  5. STEP 5: Compare before and after correction

    Run the same summarization on the uncorrected transcript and compare. You should see that proper nouns and dates become correct only after fixing the transcript.

Optional

Output as meeting minutes. Specify the format: Decisions / Action items / Due dates. Notice that without speaker information the "person responsible" field may be blank, unknown, or guessed.

Handle audio over 30 minutes by splitting it into 29-second chunks. Set up a Python virtual environment, install requests and pydub, and use splitmp3.py. A combined splitmp3+summary.py script can produce transcript_full.txt and transcript_summary.md at once.
