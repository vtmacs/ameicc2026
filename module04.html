Overview 1: The Environment We’ll Build

The Environment We’ll Build

Set up a Windows + Linux environment, and inside that a Python virtual environment, on your PC. The stack is WSL + Python virtual env (venv) + Flask.

The System We’ll Build

The user is on the left, AI Engine on the right. The question goes out, and the answer comes back. The account token is held only by Flask; it stays hidden from the browser and JavaScript.

Overall Structure (Data Flow)

Until now you called AI Engine directly with curl; now you call it through the browser and Flask. The browser sends the question to Flask, Flask calls AI Engine with requests, and the response is returned to the browser.

Why Flask Is Needed

  • Entry point: receives requests from the browser (routing).
  • Mediator: calls AI Engine with requests and formats the result before returning it.
  • Token secrecy: holds the account token on the backend, never exposing it to the browser.

What Is venv?

A separate, independent Python environment (virtual environment). Using venv avoids dependency conflicts, protects other projects, installs only what you need, and makes the environment easy to reproduce. This time we’ll create a dedicated box with only Flask and requests installed.

Overview 2: curl vs. Web App

How We’ve Done It So Far

In sessions 1–3, you used curl from the terminal to call AI Engine directly. It works, but it’s all self-contained inside your own terminal.

Web App: The Challenge

  • A command every time: users must remember the terminal and the command.
  • The token is exposed: the token rides along in the command. Share it, and it leaks.
  • No screen: no input field, no result display — you can’t hand it to someone.

What It Means to Turn This Into a Web App

A screen instead of a command; backend processing instead of manual steps. By operating the browser, the user can trigger a call to AI Engine.

Why a Server Needs to Sit in Between

Anyone can view the browser’s code, so secrets belong on the server side. Flask holds the token and never exposes it to the browser. Processing that holds a secret, plus input validation and result formatting, all happens on the server.

Hands-On 1: Environment Setup

Set up the runtime environment so the Web app can run.

Required

  • Download and extract the distributed files into WSL
  • Create the correct folder structure (templates/ and static/)
  • Create and enter a Python virtual environment
  • Install Flask and requests
  • Set the AI_ENGINE_TOKEN environment variable

Steps

  1. STEP 1: Download and extract the files

    Download the ZIP and extract it directly into your WSL home directory. Rename the extracted folder from module4-src to 04_rag-web-app.

    Download module4-src.zip

    You can also use Windows Explorer: open \\wsl.localhost\Ubuntu\home\{username}, extract the ZIP there, and rename the folder.

  2. STEP 2: Create the correct folder structure

    Move index.html into templates/, and move app.js and style.css into static/. app.py, requirements.txt, and README.md stay at the top level.

    cd ~/04_rag-web-app
mkdir templates static
mv index.html templates/
mv app.js style.css static/
ls
ls templates static
  3. STEP 3: Create a virtual environment

    Create a dedicated Python environment inside 04_rag-web-app. You only need to do this once.

    python3 -m venv venv
  4. STEP 4: Enter the virtual environment

    Activate the environment. The prompt will show (venv) at the front. Do all remaining work with (venv) showing.

    source venv/bin/activate
  5. STEP 5: Install the packages

    Install Flask and requests from requirements.txt. Check with pip list.

    pip install -r requirements.txt
pip list | grep -E "Flask|requests"
  6. STEP 6: Set the token

    Set the account token as an environment variable. Flask reads it from here; the browser and JS never see it.

    export AI_ENGINE_TOKEN="${AI_ENGINE_TOKEN}"
echo $AI_ENGINE_TOKEN

Setup Complete Checklist

  • 04_rag-web-app has templates/ and static/ laid out correctly
  • (venv) shows at the start of the prompt
  • pip list has Flask and requests
  • echo $AI_ENGINE_TOKEN shows the token

Hands-On 2: Filling In the Code

Think about where in the code the values you typed with curl should go, then fill in the blanks.

The Big Picture of the Blanks

There are 3 groups, 7 blanks in total. Build → Send → Receive — that’s the order we’ll follow.

  • Build what to send: app.py build_payload (__(1)__ __(2)__ __(3)__)
  • Send what you built: app.py requests.post (__(4)__ __(5)__)
  • Retrieve the result: app.js (data.__(1)__ data.__(2)__)

Build What to Send

Put the values you passed via --data into the payload. The variables query, top_k, and threshold already hold the screen input.

Show answer 
def build_payload(query, top_k, threshold):
    payload = {
        "model": EMBEDDING_MODEL,
        "chat_model": CHAT_MODEL,
        "query": query,
        "top_k": top_k,
        "threshold": threshold,
        "distance_type": DISTANCE_TYPE,
    }

Send What You Built

Map curl’s destination URL to the first argument of requests.post, and curl’s --data to the json= keyword.

Show answer 
response = requests.post(
    AI_ENGINE_URL,
    headers=headers,
    json=payload,
    timeout=REQUEST_TIMEOUT,
)

Retrieve the Result That Comes Back

Pull the answer and its sources out of the JSON returned from Flask. Use the JSON key names directly.

Show answer 
// Display the answer and its sources
showAnswer(data.answer);
showSources(data.sources);

Wrapping Up the Blanks

  • app.py build_payload: query / top_k / threshold
  • app.py requests.post: AI_ENGINE_URL / payload
  • app.js response: data.answer / data.sources

Hands-On 3: Run the Web App

Start the server, ask a question from the browser, and finally shut the server down.

Running Flow

  1. Enter (venv) if it’s not showing
  2. Start the server with python app.py
  3. Open the displayed URL in your browser
  4. Shut it down with Ctrl + C

Start the Server

Make sure (venv) is active and the token is set, then start the Flask development server.

echo $AI_ENGINE_TOKEN
python app.py

What You’ll See on Startup

Once it starts, the terminal shows the app URL. Debug mode is on, so saving your code reloads it automatically.

 * Serving Flask app 'app'
 * Debug mode: on
 * Running on http://127.0.0.1:5000
Press CTRL+C to quit

Why 127.0.0.1:5000?

127.0.0.1 means the server stays inside your own PC and is never exposed externally. 5000 is Flask’s default development port. It is specified in app.run(host="127.0.0.1", port=5000).

Open It in Your Browser

Open http://127.0.0.1:5000, type your question, set top_k / threshold, and press Ask. The answer and its sources (name, chunk number, distance, content) will appear.

Try It Out

  • Ask about something not in your registered documents and see how the app responds.
  • Register a new document in the control panel, then ask about it.
  • Ask in a different language than your registered documents and observe search quality.

Shut Down the Server

When you’re done, press Ctrl + C in the terminal to stop the server. To run it again, use python app.py. To leave the virtual environment, use deactivate.

Add a Read-Aloud Feature

Add a button that sends the displayed answer text to a new Flask route /api/speak, calls AI Engine’s text-to-speech API, and plays the returned WAV audio in the browser.

SPEECH_URL = "https://api.ai.sakura.ad.jp/v1/audio/speech"

@app.route("/api/speak", methods=["POST"])
def speak():
    text = request.get_json().get("text", "")
    payload = {
        "model": "<speech model ID>",
        "voice": "<voice ID>",
        "input": text
    }
    headers = {"Authorization": f"Bearer {os.getenv(TOKEN_ENV_NAME)}"}
    r = requests.post(SPEECH_URL, headers=headers, json=payload, timeout=60)
    return Response(r.content, mimetype="audio/wav")
