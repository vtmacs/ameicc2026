Overview 1: What Is Multimodal AI?

Modality and Multimodal

A modality is a type of data, such as text, images, audio, video, or sensor data. Multimodal AI is an AI technology that can process and integrate multiple types of data simultaneously.

Differences Between Single-Modal and Multimodal AI

Single-modal AI handles only one type of data at a time, such as text only or images only. Multimodal AI combines multiple types of data to achieve deeper understanding and reasoning.

Examples of Multimodal AI Applications

  • Images and text: summarizing and explaining figures and tables, visual Q&A
  • Audio and text: natural voice interaction, context-aware explanations
  • Sensor information and text: situation analysis from camera or sensor data, robot control
  • Decision support: integrated analysis across multiple information sources for healthcare, manufacturing, and security

How AI "Understands" Images

A Visual Language Model (VLM) combines a vision encoder that reads image features with a Large Language Model (LLM) that understands text. Image features are converted into a form the LLM can process, and the model generates a text response based on both inputs.

Differences from "OCR + LLM"

  • OCR: finds text in images and converts it to text
  • VLM: looks at images and text together to understand meaning and structure

SAKURA AI Engine and Public Preview Models

SAKURA AI Engine provides multimodal models as public preview models aimed at collecting user feedback. The model used in this module is preview/Qwen3-VL-30B-A3B-Instruct, a Vision-Language model in the Qwen series.

Hands-On 1: Multimodal Model Operation Verification

Verify that the multimodal model responds to a text-only request before adding images.

Required

  • Set the account token as an environment variable
  • Send a text-only chat request to the model
  • Check the response content and usage

Steps

  1. STEP 1: Set the environment variable

    Make sure your Account Token environment variable is set.

    echo $AI_ENGINE_TOKEN
# If nothing appears, set it again
export AI_ENGINE_TOKEN="<issued account token>"
  2. STEP 2: Send a text-only chat request

    Send a simple text message to preview/Qwen3-VL-30B-A3B-Instruct. The content array is used even for text-only input.

    curl -X POST "https://api.ai.sakura.ad.jp/v1/chat/completions" \
  -H "Authorization: Bearer ${AI_ENGINE_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "preview/Qwen3-VL-30B-A3B-Instruct",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "Hello"
          }
        ]
      }
    ],
    "temperature": 0.7,
    "max_tokens": 1000,
    "stream": false
  }' | json_pp

    Note: jq is a popular JSON formatter. Since software installation is not permitted in this environment, we use the built-in json_pp command instead.

  3. STEP 3: Review the response

    The response contains the answer text, finish_reason, and usage. Check that the model responded normally.

    content: the generated answer

    finish_reason: stop means the response completed normally

    usage: number of tokens consumed

Common Errors and Solutions

Error Cause Solution
400 Bad Request Invalid request parameter Check the JSON structure and the model name prefix
401 Unauthorized Token not specified Run echo $AI_ENGINE_TOKEN and confirm the token is set

Request Parameters

Parameter Meaning
modelName of the AI model to use
messagesConversation content (role and content)
roleSpeaker role: user = user, system = instruction to AI
contentMessage body; this is where you add text and images
temperatureRandomness of the response
max_tokensMaximum number of tokens generated
streamResponse delivery method

Progress Check

  • Set the account token environment variable
  • Sent a text-only request and received a response
  • Confirmed content, finish_reason, and usage

Hands-On 2: Image Recognition with URL and Base64

Send images to the API using a public URL and a local Base64-encoded file.

Two Methods of Image Transmission

Method Advantage Limitation
Image URL Request body stays small (a few KB) Cannot access private or local images
Base64 encoding Local or private images can be embedded directly Increases data size and may exceed command-line limits

Steps

  1. STEP 1: Send an image using a public URL

    Include a publicly accessible image URL in the request. Multiple content items (text and image) can be placed in the same message.

    curl -X POST "https://api.ai.sakura.ad.jp/v1/chat/completions" \
  -H "Authorization: Bearer ${AI_ENGINE_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "preview/Qwen3-VL-30B-A3B-Instruct",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "Please describe this image briefly."
          },
          {
            "type": "image_url",
            "image_url": {
              "url": "https://s3.tky01.sakurastorage.jp/ai-kentei/sakura-office.jpg"
            }
          }
        ]
      }
    ],
    "temperature": 0.7,
    "max_tokens": 2000,
    "stream": false
  }' | json_pp
  2. STEP 2: Review the response

    The response describes the image in natural language. Check the content field.

  3. STEP 3: Download the image to your local PC

    Create the work folder and download the sample image.

    mkdir -p ~/03_Multimodal
cd ~/03_Multimodal
wget "https://s3.tky01.sakurastorage.jp/ai-kentei/flower.jpg" -O flower.jpg
ls -lh flower.jpg
  4. STEP 4: Verify the saved image

    Open File Explorer and navigate to the following folder:

    Linux > Ubuntu > home > {username} > 03_Multimodal

    Alternatively, enter the following path directly in the File Explorer address bar:

    \\wsl.localhost\Ubuntu\home\{username}\03_Multimodal

    Note: Replace {username} with your WSL username.

  5. STEP 5: Send a local image as Base64

    Embed the local image directly in the request using a data URI. The -w 0 option prevents line breaks in the Base64 output.

    curl -X POST "https://api.ai.sakura.ad.jp/v1/chat/completions" \
  -H "Authorization: Bearer ${AI_ENGINE_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "preview/Qwen3-VL-30B-A3B-Instruct",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "Please describe this image briefly."
          },
          {
            "type": "image_url",
            "image_url": {
              "url": "data:image/jpeg;base64,'$(base64 -w 0 flower.jpg)'"
            }
          }
        ]
      }
    ],
    "temperature": 0.7,
    "max_tokens": 2000,
    "stream": false
  }' | json_pp
  6. STEP 6: Review the response

    Confirm that the local image is described in the content field.

Progress Check

  • Sent an image by URL and received a description
  • Downloaded the image to the local PC
  • Sent the local image as Base64 and received a description

Hands-On 3: Base64 Image Processing Using JSON Files

Send a Base64-encoded image via a JSON file to avoid command-line length limits.

Command-Line Length Limits

High-resolution images can produce Base64 strings of millions of characters. Sending them directly in a curl command may exceed the OS command-line limit and cause Argument list too long. The solution is to save the request body to a JSON file and send it with curl -d @file or --data-binary @file.

Steps

  1. STEP 1: Convert the image to Base64

    Convert the local image to a Base64 string and save it to a file.

    cd ~/03_Multimodal/
base64 -w 0 flower.jpg > flower.b64
  2. STEP 2: Write the request to a JSON file

    Create request.json with the Base64 string embedded via command substitution.

    cat > request.json <<EOF
{
  "model": "preview/Qwen3-VL-30B-A3B-Instruct",
  "messages": [
    {
      "role": "user",
      "content": [
        { "type": "text", "text": "Please describe this image briefly." },
        {
          "type": "image_url",
          "image_url": {
            "url": "data:image/jpeg;base64,$(cat flower.b64)"
          }
        }
      ]
    }
  ],
  "temperature": 0.7,
  "max_tokens": 2000,
  "stream": false
}
EOF
  3. STEP 3: Send the request with the JSON file

    Use --data-binary @request.json to send the file contents as the request body.

    curl -X POST "https://api.ai.sakura.ad.jp/v1/chat/completions" \
  -H "Authorization: Bearer ${AI_ENGINE_TOKEN}" \
  -H "Content-Type: application/json" \
  --data-binary @request.json | json_pp
  4. STEP 4: Review the response

    Confirm that the content field contains a description of the image.

Progress Check

  • Converted the image to Base64
  • Created request.json with the Base64 image
  • Sent the request using the JSON file and received a response

Hands-On 4: Development and Practical Considerations

Try Image Analysis with Your Own Images

Upload handwritten notes, complex diagrams, or photos and evaluate whether the model recognizes and explains them as expected.

  • Store image files in ~/03_Multimodal
  • Update the file name in the code to match your image
  • Use the JSON file approach from Hands-On 3 for large images
  • Do not use images containing personal or confidential information

Example Image Analysis Challenges

  • Text extraction: read text from signs or receipts and structure the result as JSON
  • Object counting: test how accurately the model counts multiple objects in a photo
  • Handwritten notes / whiteboards: summarize content and extract action items

Practical Points

  • Resolution and cost: higher resolution images consume more vision tokens, increasing latency and cost
  • Vision prompting: explicitly tell the model where to focus, e.g. "Describe the table in the upper-right corner"

Optional: Try Other Models and Combine APIs

Try a coding-focused model such as Qwen3.6-35B-A3B or gemma-4-31B-it to generate HTML/CSS from screenshots. You can also combine the multimodal API with Whisper or RAG to build a practical AI application.

Please keep usage of Kimi model to a minimum to avoid excessive load.
